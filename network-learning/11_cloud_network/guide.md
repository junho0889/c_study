# ■■■ 클라우드 네트워킹 완전 가이드 ■■■

> 클라우드 환경에서의 네트워크 설계, VPC, 서브넷, 보안 그룹,
> 그리고 하이브리드 클라우드 아키텍처를 학습합니다.

## 1. VPC (Virtual Private Cloud) 개념

```
┌──────────────────────────────────────────────────────────────┐
│  VPC: 클라우드 내에서 논리적으로 격리된 가상 네트워크        │
│                                                              │
│  비유: 클라우드라는 건물에서 "내 회사 전용 층"을 임대       │
│        → 다른 고객과 완전히 격리                            │
│        → 내 마음대로 방(서브넷)을 나누고                    │
│        → 출입 규칙(보안 그룹)을 설정                        │
│                                                              │
│   ┌──────────────────────────────────────┐                   │
│   │  VPC (10.0.0.0/16)                   │                   │
│   │  ┌─────────────┐ ┌─────────────┐    │                   │
│   │  │ Public      │ │ Private     │    │                   │
│   │  │ Subnet      │ │ Subnet      │    │                   │
│   │  │ 10.0.1.0/24 │ │ 10.0.2.0/24 │    │                   │
│   │  │ [Web Server]│ │ [DB Server] │    │                   │
│   │  └─────────────┘ └─────────────┘    │                   │
│   └──────────────────────────────────────┘                   │
│                                                              │
│  핵심 구성 요소:                                             │
│  VPC, Subnet, Route Table, IGW, NAT GW,                     │
│  Security Group, NACL, VPC Peering, VPN GW                  │
└──────────────────────────────────────────────────────────────┘
```

## 2. 서브넷 (Public / Private)

```
┌──────────────────────────────────────────────────────────────┐
│                      인터넷                                   │
│                        │                                     │
│                   ┌────▼────┐                                │
│                   │  IGW    │  Internet Gateway              │
│                   └────┬────┘                                │
│   ┌────────────────────┼────────────────────────┐            │
│   │          VPC (10.0.0.0/16)                  │            │
│   │                    │                         │            │
│   │ ┌──────────────┐  │  ┌──────────────┐       │            │
│   │ │Public Subnet │  │  │Private Subnet│       │            │
│   │ │10.0.1.0/24   │  │  │10.0.2.0/24   │       │            │
│   │ │              │  │  │              │       │            │
│   │ │ [Web/ALB]    │  │  │ [DB/App]     │       │            │
│   │ │ 공인 IP 있음 │  │  │ 공인 IP 없음 │       │            │
│   │ │              │  │  │      │       │       │            │
│   │ │ Route:       │  │  │ ┌────▼─────┐ │       │            │
│   │ │ 0.0.0.0/0    │  │  │ │ NAT GW   │ │       │            │
│   │ │ → IGW        │  │  │ └──────────┘ │       │            │
│   │ │              │  │  │ Route:       │       │            │
│   │ │              │  │  │ 0.0.0.0/0   │       │            │
│   │ │              │  │  │ → NAT GW    │       │            │
│   │ └──────────────┘  │  └──────────────┘       │            │
│   └─────────────────────────────────────────────┘            │
│                                                              │
│  Public Subnet: IGW로 라우팅, 인터넷에서 직접 접근 가능     │
│  Private Subnet: NAT GW로만 인터넷 (아웃바운드만)           │
│                                                              │
│  ★ DB는 절대 Public Subnet에 놓지 마세요!                   │
└──────────────────────────────────────────────────────────────┘
```

## 3. Internet Gateway vs NAT Gateway

```
┌───────────────┬──────────────────┬───────────────────────────┐
│               │ Internet Gateway │ NAT Gateway               │
├───────────────┼──────────────────┼───────────────────────────┤
│ 방향          │ 양방향           │ 아웃바운드만              │
│ 서브넷        │ Public           │ Private → 인터넷          │
│ 비용          │ 무료             │ 시간당 + 데이터 전송     │
│ 가용성        │ AWS 관리         │ AZ별 배포 권장           │
└───────────────┴──────────────────┴───────────────────────────┘

  ★ 비용 절약: S3, DynamoDB는 VPC Endpoint 사용 (NAT 불필요)
```

## 4. Security Group vs NACL

```
┌───────────────┬──────────────────┬───────────────────────────┐
│               │ Security Group   │ NACL                      │
├───────────────┼──────────────────┼───────────────────────────┤
│ 적용 수준     │ 인스턴스 (ENI)   │ 서브넷                    │
│ 상태          │ Stateful         │ Stateless                 │
│               │ (응답 자동 허용) │ (각각 설정 필요)         │
│ 규칙 유형     │ 허용만           │ 허용 + 차단              │
│ 규칙 처리     │ 모든 규칙 평가   │ 번호 순서대로            │
│ 기본 정책     │ 모두 차단        │ 모두 허용 (기본 NACL)    │
└───────────────┴──────────────────┴───────────────────────────┘

  웹서버 SG 예시:
  Inbound: HTTP(80) 0.0.0.0/0, HTTPS(443) 0.0.0.0/0, SSH(22) 관리IP만
  Outbound: All traffic → 0.0.0.0/0

  ★ Stateful: 인바운드 허용하면 응답 자동 허용 (아웃바운드 규칙 불필요)
  ★ Stateless(NACL): 인/아웃 각각 설정, Ephemeral Port 허용 필수
```

## 5. VPC Peering과 Transit Gateway

```
┌──────────────────────────────────────────────────────────────┐
│  VPC Peering (1:1):                                          │
│  VPC-A ◄═══► VPC-B  (간단, 비용 낮음, 전이적 라우팅 불가)  │
│                                                              │
│  Transit Gateway (허브-스포크):                               │
│  VPC-A ──┐                                                   │
│  VPC-B ──┼──► [Transit GW] ──► On-Premise                   │
│  VPC-C ──┘    (중앙 허브)                                   │
│                                                              │
│  VPC 3~4개: Peering 충분                                     │
│  VPC 5개+: Transit Gateway 고려                              │
└──────────────────────────────────────────────────────────────┘
```

## 7. 하이브리드 클라우드 네트워크

```
┌──────────────────────────────────────────────────────────────┐
│  ┌──────────────────┐          ┌──────────────────┐         │
│  │   온프레미스      │  VPN or  │   AWS Cloud       │         │
│  │   10.1.0.0/16    │◄════════►│   10.0.0.0/16    │         │
│  │   서버, DB       │  Direct  │   VPC, App, DB   │         │
│  │   방화벽         │  Connect │   Replica        │         │
│  └──────────────────┘          └──────────────────┘         │
│                                                              │
│  연결 방법:                                                  │
│  VPN: ~1.25Gbps, 비용 낮음, 지연 변동                       │
│  Direct Connect: 1~100Gbps, 비용 높음, 지연 일정            │
│                                                              │
│  ★ IP 충돌 주의: 온프레미스와 클라우드 IP 겹치지 않도록!    │
│  ★ DNS 통합: 온프레미스 DNS ↔ Route53 Resolver              │
└──────────────────────────────────────────────────────────────┘
```

## 9. CDN (Content Delivery Network)

```
┌──────────────────────────────────────────────────────────────┐
│  CDN: 전세계 엣지 서버에 콘텐츠를 캐시하여 빠르게 전달     │
│                                                              │
│  CDN 없이: 서울→미국 오리진 ~200ms                          │
│  CDN 있을때: 서울 POP에서 캐시 ~5ms                         │
│                                                              │
│  서비스 비교:                                                │
│  CloudFront(AWS), Cloudflare(무료 플랜), Azure CDN,         │
│  Cloud CDN(GCP), Akamai(엔터프라이즈), Fastly(실시간)       │
│                                                              │
│  캐시: 정적(TTL 길게) vs 동적(TTL 짧게/캐시 안함)          │
│  ★ CDN은 성능뿐 아니라 DDoS 방어에도 효과적                │
└──────────────────────────────────────────────────────────────┘
```

## 10. 클라우드 네트워크 설계 체크리스트

```
┌──────────────────────────────────────────────────────────────┐
│  ■ VPC 설계                                                  │
│  □ CIDR /16 (나중에 변경 불가!)                             │
│  □ 온프레미스 IP와 겹치지 않도록                            │
│  □ 멀티 AZ 서브넷 (최소 2개 AZ)                            │
│  □ Public/Private 분리                                       │
│                                                              │
│  ■ 보안                                                      │
│  □ Security Group: 최소 권한                                 │
│  □ DB는 Private에만, Bastion/SSM으로 접근                   │
│  □ VPC Flow Logs + GuardDuty 활성화                         │
│                                                              │
│  ■ 비용 최적화                                               │
│  □ VPC Endpoint (NAT GW 비용 절약)                          │
│  □ 같은 AZ 내 통신 (AZ 간 전송비 절약)                     │
│  □ 미사용 Elastic IP 해제                                   │
│                                                              │
│  ■ 고가용성                                                  │
│  □ 최소 2개 AZ, ALB/NLB 부하 분산                           │
│  □ Route53 Health Check + 장애 조치                         │
└──────────────────────────────────────────────────────────────┘
```

## 부록: VPC 설계 실전 예시 (AWS)

### 프로덕션 VPC 아키텍처

```
┌──────────────────────────────────────────────────────────────┐
│  VPC: 10.0.0.0/16 (ap-northeast-2, 서울)                    │
│                                                              │
│  ┌─── AZ-a ────────────┐  ┌─── AZ-c ────────────┐          │
│  │                      │  │                      │          │
│  │ Public-1a            │  │ Public-1c            │          │
│  │ 10.0.1.0/24          │  │ 10.0.2.0/24          │          │
│  │ [ALB] [NAT GW]      │  │ [ALB] [Bastion]      │          │
│  │                      │  │                      │          │
│  │ Private-1a           │  │ Private-1c           │          │
│  │ 10.0.10.0/24         │  │ 10.0.11.0/24         │          │
│  │ [App Server]         │  │ [App Server]         │          │
│  │                      │  │                      │          │
│  │ DB-1a                │  │ DB-1c                │          │
│  │ 10.0.20.0/24         │  │ 10.0.21.0/24         │          │
│  │ [RDS Primary]        │  │ [RDS Standby]        │          │
│  │                      │  │                      │          │
│  └──────────────────────┘  └──────────────────────┘          │
│                                                              │
│  Route Tables:                                               │
│  Public RT:  0.0.0.0/0 → IGW                               │
│  Private RT: 0.0.0.0/0 → NAT GW                            │
│  DB RT:      10.0.0.0/16 → local (인터넷 라우팅 없음)      │
│                                                              │
│  Security Groups:                                            │
│  ALB-SG:     Inbound 80,443 from 0.0.0.0/0                 │
│  App-SG:     Inbound 8080 from ALB-SG                      │
│  DB-SG:      Inbound 3306 from App-SG                      │
│  Bastion-SG: Inbound 22 from 사무실IP/32                   │
└──────────────────────────────────────────────────────────────┘
```

### Terraform으로 VPC 생성 (코드 예시)

```
┌──────────────────────────────────────────────────────────────┐
│  # VPC 생성                                                  │
│  resource "aws_vpc" "main" {                                 │
│    cidr_block           = "10.0.0.0/16"                     │
│    enable_dns_support   = true                               │
│    enable_dns_hostnames = true                               │
│    tags = { Name = "production-vpc" }                       │
│  }                                                           │
│                                                              │
│  # Public 서브넷                                             │
│  resource "aws_subnet" "public_1a" {                        │
│    vpc_id            = aws_vpc.main.id                      │
│    cidr_block        = "10.0.1.0/24"                        │
│    availability_zone = "ap-northeast-2a"                    │
│    map_public_ip_on_launch = true                           │
│    tags = { Name = "public-1a" }                            │
│  }                                                           │
│                                                              │
│  # Internet Gateway                                          │
│  resource "aws_internet_gateway" "main" {                   │
│    vpc_id = aws_vpc.main.id                                 │
│  }                                                           │
│                                                              │
│  # Security Group                                            │
│  resource "aws_security_group" "web" {                      │
│    vpc_id = aws_vpc.main.id                                 │
│    ingress {                                                 │
│      from_port   = 80                                       │
│      to_port     = 80                                       │
│      protocol    = "tcp"                                    │
│      cidr_blocks = ["0.0.0.0/0"]                           │
│    }                                                         │
│  }                                                           │
└──────────────────────────────────────────────────────────────┘
```

### VPC Endpoint로 비용 절약

```
┌──────────────────────────────────────────────────────────────┐
│  NAT GW 통해 S3 접근: 데이터 전송 비용 발생!               │
│  VPC Endpoint 통해 S3 접근: 무료! (같은 리전)               │
│                                                              │
│  Gateway Endpoint (무료):                                    │
│  - S3, DynamoDB                                              │
│  - Route Table에 자동 추가                                  │
│                                                              │
│  Interface Endpoint (시간당 비용):                           │
│  - SQS, SNS, KMS, CloudWatch, ECR 등                       │
│  - ENI 생성 (Private IP 할당)                               │
│                                                              │
│  ★ S3를 많이 사용한다면 Gateway Endpoint 필수!              │
│  ★ 월 수백 GB S3 트래픽 → NAT GW 비용 수십 달러 절약      │
└──────────────────────────────────────────────────────────────┘
```

---

> **클라우드 네트워크는 온프레미스 네트워크의 확장입니다.**
> **기본 개념(IP, 서브넷, 라우팅, 방화벽)은 동일하며,**
> **클라우드 고유 서비스(IGW, NAT GW, SG, VPC Peering)가 추가된 것입니다.**
> **온프레미스를 이해하면 클라우드도 쉽습니다.**
