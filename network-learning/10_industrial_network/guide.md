### 1.2 네트워크 토폴로지 선택

#### 3-Tier 아키텍처 (대규모)

```
┌──────────────────────────────────────────────────────────────┐
│              ┌─────────────┐  ┌─────────────┐               │
│              │  Core SW 1  │──│  Core SW 2  │               │
│              └──────┬──────┘  └──────┬──────┘               │
│         ┌───────────┼────────────────┼───────────┐           │
│    ┌────▼───┐  ┌────▼───┐      ┌────▼───┐  ┌────▼───┐      │
│    │Dist SW1│  │Dist SW2│      │Dist SW3│  │Dist SW4│      │
│    └────┬───┘  └────┬───┘      └────┬───┘  └────┬───┘      │
│    ┌────▼───┐  ┌────▼───┐      ┌────▼───┐  ┌────▼───┐      │
│    │Acc SW  │  │Acc SW  │      │Acc SW  │  │Acc SW  │      │
│    │1F 사무 │  │2F 사무 │      │3F 개발 │  │서버실  │      │
│    └────────┘  └────────┘      └────────┘  └────────┘      │
│                                                              │
│  Core: L3 스위치, VLAN간 라우팅, 이중화                     │
│  Distribution: 정책 적용, ACL, QoS                           │
│  Access: 사용자 연결, PoE                                    │
└──────────────────────────────────────────────────────────────┘
```

#### Collapsed Core (중소기업, 2-Tier)

```
┌──────────────────────────────────────────────────────────────┐
│           Core + Distribution 통합 (L3 스위치)               │
│              ┌────────────────────────┐                      │
│              │    Core/Dist Switch    │                      │
│              └───┬──────┬──────┬──────┘                      │
│             ┌────▼┐ ┌───▼──┐ ┌─▼────┐                       │
│             │AccSW│ │AccSW │ │AccSW │                       │
│             │사무실│ │개발  │ │서버  │                       │
│             └─────┘ └──────┘ └──────┘                       │
│  ★ 50~200명 규모에 적합, 비용 절감                          │
└──────────────────────────────────────────────────────────────┘
```

### 1.4 대역폭 계산

```
┌──────────────────────────────────────────────────────────────┐
│  서비스별 대역폭: 웹(1~3M), 화상회의(4~6M), VoIP(0.1M)     │
│                                                              │
│  공식: 사용자수 × 평균대역폭 × 동시사용률 × 오버헤드(1.3)  │
│  예: 100명 × 3Mbps × 0.7 × 1.3 = 273 Mbps → 500M 회선     │
│                                                              │
│  ★ 현재 사용량의 2~3배로 여유있게 계획                      │
└──────────────────────────────────────────────────────────────┘
```

## 2. 물리적 인프라

### 2.1 케이블링

```
┌──────────────────────────────────────────────────────────────┐
│                    케이블 종류 비교표                         │
├──────────┬──────────┬──────────┬──────────┬─────────────────┤
│ 케이블   │ 최대속도 │ 최대거리 │ 가격     │ 용도            │
├──────────┼──────────┼──────────┼──────────┼─────────────────┤
│ Cat5e    │ 1 Gbps   │ 100m     │ 저렴     │ 기존 설치       │

│ Cat6a    │ 10 Gbps  │ 100m     │ 약간높음 │ 권장 표준       │
│ Cat8     │ 40 Gbps  │ 30m      │ 매우높음 │ 데이터센터      │
│ MM 광섬유│ 10 Gbps  │ 300m     │ 보통     │ 건물 내 백본    │

  ★ 신규 설치 권장: Cat6a (10Gbps, 100m, 미래 대비)
```

### 2.2 서버실 / UPS

```
┌──────────────────────────────────────────────────────────────┐
│  서버실 환경: 온도 22~24°C, 습도 45~50%                     │
│  랙 구성: 네트워크 장비 상단, 서버 하단 (열 관리)           │
│  전원: 이중 인입 + UPS + 발전기 (ATS 자동전환)              │
│  PDU: A/B 이중 전원 분배                                     │
│                                                              │
│  UPS 용량 = 총 소비전력(W) × 시간(h) × 1.3(여유)           │
│  예: 2000W × 0.5h × 1.3 = 1300Wh → 1.5kVA UPS             │
└──────────────────────────────────────────────────────────────┘
```

## 5. VLAN 설계

```
┌──────────────────────────────────────────────────────────────┐
│  VLAN 번호 체계:                                             │
│  VLAN 1   = 기본 (사용하지 않음!)                           │
│  VLAN 10  = 서버        VLAN 20  = 사무실                   │
│  VLAN 30  = 개발        VLAN 40  = IoT                      │
│  VLAN 50  = 게스트      VLAN 60  = VoIP                     │
│  VLAN 99  = 관리        VLAN 200 = DMZ                      │
│  VLAN 999 = 블랙홀 (미사용 포트)                            │
│                                                              │
│  VLAN 간 통신 규칙:                                          │
│  → = 허용, X = 차단, △ = 제한적                            │
│                                                              │
│  From\To  │서버│사무│개발│게스트│DMZ │관리│                  │
│  서버     │ → │ → │ → │  X  │ X │ X │                      │
│  사무실   │ △ │ → │ X │  X  │ X │ X │                      │
│  개발     │ △ │ X │ → │  X  │ → │ X │                      │
│  게스트   │ X │ X │ X │  → │ X │ X │ (인터넷만)            │
│  관리     │ → │ → │ → │  → │ → │ → │                      │
│                                                              │
│  ★ VLAN 1 사용 금지, 미사용 포트는 VLAN 999 할당            │
└──────────────────────────────────────────────────────────────┘
```

## 6. VPN 구축

```
┌──────────────────────────────────────────────────────────────┐
│                    VPN 프로토콜 비교표                        │
├──────────────┬──────────┬──────────┬──────────┬─────────────┤
│              │ IPSec    │ OpenVPN  │WireGuard │ SSL VPN     │
├──────────────┼──────────┼──────────┼──────────┼─────────────┤
│ 속도         │ 빠름     │ 보통     │ 매우빠름 │ 보통        │
│ 설정 난이도  │ 어려움   │ 중간     │ 쉬움     │ 쉬움        │
│ NAT 통과     │ 어려움   │ 쉬움     │ 쉬움     │ 쉬움        │
│ 적합 용도    │ 지사 연결│ 범용     │ 고속     │ 재택근무    │
└──────────────┴──────────┴──────────┴──────────┴─────────────┘

  Site-to-Site: IPSec 또는 WireGuard (본사-지사)
  Remote Access: WireGuard 또는 SSL VPN (재택근무)

  Split Tunnel: 회사 트래픽만 VPN (빠름, 보안 약함)
  Full Tunnel: 모든 트래픽 VPN (느림, 보안 강함)
```

## 8. 고가용성(HA) 설계

```
┌──────────────────────────────────────────────────────────────┐
│  Active-Standby: 한 대 운영, 한 대 대기 (단순, 자원 낭비)  │
│  Active-Active: 둘 다 운영, 부하 분산 (효율적, 복잡)       │
│                                                              │
│  SLA별 허용 다운타임:                                        │
│  99%=3.65일, 99.9%=8.7시간, 99.99%=52분, 99.999%=5.3분     │
│                                                              │
│  Link Aggregation (LACP):                                    │
│  4x 1Gbps 물리 링크 = 논리적 4Gbps (대역폭 + 이중화)       │
│                                                              │
│  장애 시나리오:                                              │
│  ISP 장애 → 이중 ISP   │ 방화벽 → HA Pair                  │
│  코어SW → VRRP 이중화  │ 케이블 → LACP 이중경로            │
│                                                              │
│  복구 테스트: 월 1회 HA 절체, 분기 1회 전체 장애 시뮬       │
└──────────────────────────────────────────────────────────────┘
```

## 10. 트러블슈팅 가이드

### 단계별 문제 해결 (OSI 계층별)

```
┌──────────────────────────────────────────────────────────────┐
│  1. 물리(L1): 케이블, LED, 포트 교체 테스트                 │
│  2. 데이터링크(L2): MAC 테이블, VLAN, 트렁크, STP           │
│  3. 네트워크(L3): IP 설정, ping, 라우팅, traceroute         │
│  4. 전송(L4): 포트 상태, 방화벽, netstat/ss                 │
│  5. 응용(L5~7): DNS, 서비스, 로그, curl, SSL 인증서         │
└──────────────────────────────────────────────────────────────┘
```

### 흔한 문제와 해결

```
┌──────────────────┬────────────────┬──────────────────────────┐
│ 증상             │ 원인           │ 해결                     │
├──────────────────┼────────────────┼──────────────────────────┤
│ 인터넷 안 됨     │ DNS 문제       │ 8.8.8.8 ping → DNS 변경│
│ 특정 사이트 안됨 │ DNS/방화벽     │ nslookup, 방화벽 로그   │
│ 속도 느림        │ 대역폭/듀플렉스│ 사용량, 에러 카운터     │
│ 간헐적 끊김      │ 케이블/무선    │ 교체, 채널 변경         │
│ IP 충돌          │ 고정IP 중복    │ DHCP 사용, IP 대장      │
│ VPN 안 됨        │ 포트/NAT       │ UDP 500,4500, NAT-T     │
│ 프린터 연결 불가 │ VLAN 분리      │ Inter-VLAN 라우팅       │
└──────────────────┴────────────────┴──────────────────────────┘
```

### 핵심 진단 명령어

```
  ping 10.0.0.1              # 연결 확인
  tracert 8.8.8.8            # 경로 추적
  nslookup google.com        # DNS 조회
  netstat -an | findstr :80  # 포트 확인
  ipconfig /all              # IP 설정
  ipconfig /flushdns         # DNS 캐시 초기화
  arp -a                     # ARP 캐시
  route print                # 라우팅 테이블
  Test-NetConnection -p 80   # PowerShell 포트 테스트
```

## 부록 B: 실전 트러블슈팅 시나리오

### 시나리오 1: "인터넷이 안 돼요"

```
┌──────────────────────────────────────────────────────────────┐
│  1단계: 범위 확인                                            │
│  - 한 명만? → PC 문제                                       │
│  - 특정 부서? → 해당 VLAN/스위치 문제                       │
│  - 전체? → 방화벽/ISP 문제                                  │
│                                                              │
│  2단계: 단계별 확인                                          │
│  > ping 127.0.0.1          ← TCP/IP 스택 확인               │
│  > ping 10.1.20.1          ← 게이트웨이 확인                │
│  > ping 8.8.8.8            ← 인터넷 연결 확인              │
│  > ping google.com         ← DNS 확인                      │
│                                                              │
│  3단계: 결과별 조치                                          │
│  - 127.0.0.1 실패 → 네트워크 어댑터 재시작                 │
│  - GW 실패 → 케이블, VLAN, IP 설정 확인                    │
│  - 8.8.8.8 실패 → 방화벽 규칙, ISP 확인                   │
│  - google.com만 실패 → DNS 서버 변경 (8.8.8.8, 1.1.1.1)   │
└──────────────────────────────────────────────────────────────┘
```

### 시나리오 2: "속도가 느려요"

```
┌──────────────────────────────────────────────────────────────┐
│  1. 대역폭 확인: 모니터링 도구에서 사용률 확인              │
│     > 80% 이상이면 → 회선 증설 또는 QoS 적용              │
│                                                              │
│  2. 인터페이스 에러 확인:                                    │
│     > show interface GigabitEthernet1/0/1                   │
│     CRC errors, collisions → 케이블 불량/듀플렉스 불일치   │
│                                                              │
│  3. 속도/듀플렉스 확인:                                     │
│     양쪽 모두 Auto 또는 양쪽 모두 수동 설정                │
│     한쪽 Auto + 한쪽 수동 = 문제 발생!                     │
│                                                              │
│  4. DNS 지연 확인:                                           │
│     > nslookup google.com                                   │
│     응답이 느리면 → DNS 서버 변경                           │
│                                                              │
│  5. 특정 서비스만 느린 경우:                                 │
│     Wireshark로 패킷 캡처 → TCP 재전송 확인                │
└──────────────────────────────────────────────────────────────┘
```
